# Code layout

- `src/gkcore/__init__.py` will be the entry point for the gkcore app.

- `src/gkcore/routes.py` contains the mapping of all REST API endpoints to their route names.

- `src/gkcore/models/` contains database model schema of the application.

- `src/gkcore/migrations/` contains model migrations for the application.

- `src/gkcore/spec/` has OpenAPI spec files for the SwaggerUI.

- `src/gkcore/data/` has data needed for the project.

- `src/gkcore/views/` contains the logic for all API's. Each file corresponds to the specific component's API code.

- `src/gkcore/views/__init__.py` contains the logic for exception and validation handling for the APIs.

- `src/static/` dir has HSN/SAC code json file which is auto generated by the `update_fin_codes.py` script.

- `src/gkcore/scripts/` contains the scripts of the project.

- `src/gkcore/utils/` contains the helper functions for the project.

- `src/gkcore/renderers.py` contains the custom renderers for the project.

- `src/gkcore/security.py` contains the security policies for the project.

- `src/gkcore/logging.py` contains the logging structure for the project.

- We follow the [conventional commits](https://www.conventionalcommits.org/en/v1.0.0/) specification for writing commit messages.

# Merge strategy

Development happens on the `devel` branch. Create your feature branch from it, add your changes and make a merge request

`master` branch is intended for stable code. So, do not push changes to it.

# Release Strategy

Checklist:

1. Update IFSC & HSN codes with `update_fin_codes.py`
2. Git checkout to master
3. merge commits from devel -> master
4. Wait for the ci/cd pipeline to finish. Make sure all jobs are successful
5. Create a Release / tag
